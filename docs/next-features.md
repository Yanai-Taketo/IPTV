**1. ザッピング + Media Session + ショートカット**

- 巡回する並びは `state.filtered` そのもの(お気に入り先頭・最近見た順・フィルタが
  効いた「画面に見えている順」)。端では巡回せずボタンを無効化する
- `player.js` の `init(options)` に `onNavigate` を追加。位置 (`n / m ch`) はアプリ側が
  `IPTVPlayer.setNav()` で渡し、`applyFilters()` のたびに再同期する
  (再生中チャンネルが結果から外れたら操作ごと無効化)
- Media Session のメタデータは「現在番組名 + チャンネル名 + ロゴ」。既存の 30 秒
  タイマーにぶら下げて番組境界に追従し、`previoustrack`/`nexttrack` を同じザッピングへ配線
- ショートカットは m / f / ↑↓ / ←→。**プレイヤーが開いている間だけ**有効(閉じている
  ときは一覧側の操作を一切奪わない)。入力欄フォーカス中と修飾キー併用時も横取りしない
- 音量は `store.js` に足した汎用 `getPref`/`setPref` で保存・復元。ユーザーが自分で
  切ったミュートは選局をまたいで維持し、自動再生フォールバックの一時ミュートとは区別する
- 実装メモ: モーダル表示中はツールバーが inert になるため、`page.fill('#search')` は
  無効。再同期のテストは検索の `input` イベントを直接起こして行う

**3. 番組タイトル検索**

- 「番組名も検索」トグル。チャンネル情報で拾えなかったトークンだけを番組表に当てる
- 照合は全番組タイトルを繋いだ小文字列への線形検索(チャンネル単位でキャッシュ)。
  **本番データ・ブラウザ実測で初回 20.2ms / 2 回目 4.1ms**(945ch・33,811 番組、
  150ms デバウンス内)
- 一致した番組はカードに 1 行出し、テレビ欄では輪郭 + 🔍 で示す(色だけに頼らない)
- **HTML 実体参照の復号を修正**(§2-3 の前提):
  - `scripts/epg-lib.mjs` の `firstValue` が未復号のまま格納していた。本番実測で
    `&amp;` 902 件・`&nbsp;` 1 件(`Half &amp; Half` がそのまま画面に出ていた)
  - 生成側で復号し、復号後に trim / 切り詰める
  - 配信データの入れ替えは次回グラブ後なので、**クライアント側でも読み込み時に復号**する
    (schedule と詳細シャードの両方。詳細側を揃えないとタイトルで突き合わせている
    説明文が見つからなくなる)。本番データで未復号タイトルが 0 件になることを確認済み
  - 表は XML の 5 実体 + 番組表で現実に現れる範囲。未知の実体・範囲外の数値参照・
    サロゲート単体は元のまま残し、二重符号化は 1 回だけ解く

**5. Playability 履歴・前回比レポート**

- しきい値の根拠は **実際の事故データ**。2026-08-04 の 3 連続実行で
  `playable 5,846 (率 32.5%) → 751 (率 4.2%) → 5,428 (率 30.2%)` が起き、
  総 URL 数 17,968 は 3 回とも同一のまま壊れたインデックスがコミット・デプロイされた。
  健全な実行同士の変動 **-7.2%** と事故 **-87.2%** は 1 桁違うため、両者を確実に分ける
  位置に置いた: **fail = 再生可能率が前回の 50% 未満 / warn = 20% 以上の低下**
- 判定は「率」で行う。上流 `streams.json` が縮んで playable が減るのは正常なので、
  上流の異常縮小は総 URL 数側の別チェックで捕まえる。初回でも「再生可能 0 件」は異常
- `status` マップ同士の差分で 新規死亡 / 復活 / URL の増減 も内訳に出す
- ワークフローはプローブ前に前回分を退避し、**判定をコミットの前**に置く(中断すれば
  サイトは前日のインデックスのまま = 壊れた配信をしない)。上流の実変動で止まった
  ときは `workflow_dispatch` の `fail_drop` で突破できる
- 同じパターンを `grab-epg.yml` にも適用: `convertGuide` が `stats.perSite` を返し、
  グラブを試みたサイト一覧(`prepare --split-dir` のファイル名)と突き合わせて
  **番組 0 件のサイトを表と `::warning::` で名指し**する。「サイト実績ベースの
  自動デナイリスト」(§3.5)の入力がこれで揃った
- `scripts/probe-streams.mjs` は変更なし

## 2. 実環境で確認済みの既知の課題

1. **EPG: 一部サイトが GitHub ランナーから番組 0 件**(第 2 ラウンドで一次対策済み)
   - ブロック 9 サイト(`chaines-tv.orange.fr` `clickthecity.com` `distro.tv` `m.tv.sms.cz`
     `sat.tv` `tvprofil.com` `tvtv.us` `wavve.com` `zuragt.mn`)は `EXCLUDED_SITES` で
     選定から除外済み。本番で混入ゼロを確認、カバレッジは 913ch → **945ch** に増えた
   - 原因はデータセンター IP ブロックが濃厚(`zuragt.mn` は別 IP からは取得できた。
     probe の「runner-location bias」docs/playability-research.md と同根)
   - **残課題**: 除外リストは静的にハードコードされており、新たにブロックされたサイトは
     人が気づくまで死んだ選定枠を占め続ける(→ §3.5「サイト実績ベースの自動デナイリスト」)。
     第 4 ラウンドで **サイト別番組数のジョブサマリ + 0 件サイトの `::warning::`** を
     `grab-epg.yml` に入れたため、「気づく」までの時間は短縮された。残るのは
     実績を epg-data ブランチに履歴として残し、N 日連続 0 件で自動除外する部分
2. Chromium はこの開発環境の egress プロキシ経由で外部 HTTPS サイトを開けない
   (`ERR_CONNECTION_RESET`)。本番サイトのブラウザ確認は「本番データをローカルにミラーして検証」
   方式を使う(手順: 本番の `data/epg/*` を取得してローカル配信 +
   `tests/fixtures/realdata/` の API スナップショットを route で注入)
3. ~~EPG の番組タイトルは HTML エンティティが未復号のまま格納されている~~
   → **第 4 ラウンドで修正済み**(`scripts/epg-lib.mjs` の `firstValue` で復号)。
   配信データへの反映は次回グラブ後だが、クライアント側でも読み込み時に復号する
   ようにしたため画面上は解消済み。**次回グラブ後にこのクライアント側の復号を
   外してよいかは判断しないこと** — 復号済みデータに対しては no-op で、
   グラブが失敗して古いデータが残った場合の保険として機能する
