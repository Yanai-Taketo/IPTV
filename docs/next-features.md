## 2. 実環境で確認済みの既知の課題

1. **EPG: 9 サイトが GitHub ランナーから番組 0 件**
   `chaines-tv.orange.fr` `clickthecity.com` `distro.tv` `m.tv.sms.cz` `sat.tv`
   `tvprofil.com` `tvtv.us` `wavve.com` `zuragt.mn`
   - グラブプロセス自体は 40/40 成功(タイムアウト・クラッシュではない)。0 件はサイト側の応答内容
   - `zuragt.mn` は開発環境(別 IP)からは取得できた → **データセンター IP ブロックが濃厚**
     (probe の「runner-location bias」docs/playability-research.md と同根)
   - 最大の損失は `tvtv.us`(116ch)。9 サイト合計で選定枠 199ch が死んでいる
   - 回復余地は確認済み: tvtv.us がガイドを持つ 2,126 局のうち 734 局は別サイトのガイドも
     持つ(全体ではガイド保有 11,717 局中 4,853 局が 2 サイト以上)。選定からの除外 +
     再選定で実効カバレッジ約 9% 増の見込み(§3.1 / §3.5 の候補参照)
2. **Playwright テストは CI で回っていない**(ローカル実行のみ)。push/PR で回す workflow が無い
3. Chromium はこの開発環境の egress プロキシ経由で外部 HTTPS サイトを開けない
   (`ERR_CONNECTION_RESET`)。本番サイトのブラウザ確認は「本番データをローカルにミラーして検証」
   方式を使う(このセッションで実施済み。手順: 本番の `data/epg/*` を取得してローカル配信 +
   `tests/fixtures/realdata/` の API スナップショットを route で注入)

### おすすめ実装順(トップ 5)

1. **Playwright テストの CI 化**(S)— 以降の全変更の安全網。YAML 1 本 + http-server を
   devDependency 化するだけ。CI 条件(同梱 Chromium)で 14 秒グリーンなことは検証済み
2. **EPG ブロックサイトの選定除外 + 代替ガイド再選定**(S〜M)— 既知課題 §2-1 の直接対策。
   死んだ選定枠 199ch を生きたサイトへ振り直し、カバレッジ約 9% 増の見込み
   (tvtv.us の 2,126 ガイド保有チャンネル中 734 局に別サイトのガイドが実在することを確認済み)
3. **お気に入り + 最近見た履歴**(S+S、保存基盤共有で同時実装が効率的)— 定番のリテンション機能
4. **新聞テレビ欄風タイムライングリッド**(M)— サイトのデザインコンセプトに最も合致する看板機能。
   「フィルタ適用後の行のみ描画 + 時間窓を今〜+6h に限定」のスコープ固定が M 維持の条件
5. **地域(大陸)フィルタ + チャンネル現地時刻表示**(S+S)— iptv-org API の未活用データを
   すぐ価値にできる 2 件。結合キーの完全性(参照ミス 0)は実データで検証済み

### 3.1 iptv-org API の未活用データ活用

### 実装時の一般的注意

- どの機能もこのリポジトリの慣習に合わせること: ハーメチックテスト必須(tests/helpers.js の
  ルーティング機構)、EPG 関連は擬似クロック凍結(tests/epg.spec.js 参照)、
  データが無い環境でのグレースフルデグラデーション
- 複数候補が同じ基盤を共有する組み合わせ(お気に入り+履歴、州別+エリア表示、
  ザッピング+MediaSession+ショートカット)はまとめて実装すると効率が良い
