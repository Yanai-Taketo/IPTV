## 2. 実環境で確認済みの既知の課題

1. **EPG: 一部サイトが GitHub ランナーから番組 0 件**(第 2 ラウンドで一次対策済み)
   - ブロック 9 サイト(`chaines-tv.orange.fr` `clickthecity.com` `distro.tv` `m.tv.sms.cz`
     `sat.tv` `tvprofil.com` `tvtv.us` `wavve.com` `zuragt.mn`)は `EXCLUDED_SITES` で
     選定から除外済み。本番で混入ゼロを確認、カバレッジは 913ch → **945ch** に増えた
   - 原因はデータセンター IP ブロックが濃厚(`zuragt.mn` は別 IP からは取得できた。
     probe の「runner-location bias」docs/playability-research.md と同根)
   - **残課題**: 除外リストは静的にハードコードされており、新たにブロックされたサイトは
     人が気づくまで死んだ選定枠を占め続ける(→ §3.5「サイト実績ベースの自動デナイリスト」)
2. Chromium はこの開発環境の egress プロキシ経由で外部 HTTPS サイトを開けない
   (`ERR_CONNECTION_RESET`)。本番サイトのブラウザ確認は「本番データをローカルにミラーして検証」
   方式を使う(手順: 本番の `data/epg/*` を取得してローカル配信 +
   `tests/fixtures/realdata/` の API スナップショットを route で注入)
3. EPG の番組タイトルは HTML エンティティが未復号のまま格納されている
   (`scripts/epg-lib.mjs` の `firstValue`)。番組タイトル検索を実装するときに
   epg-lib 側で直すこと(反映は次回グラブ後)

### 次のおすすめ実装順(第 3 ラウンドの再評価)

1. **ザッピング(前/次選局)+ Media Session API + キーボードショートカット**(M+S、同時実装)
   — プレイヤーを「テレビ」にする 3 点コンボ。お気に入り・履歴ができた今、
   「お気に入りのみ + ザッピング」が実質マイチャンネル巡回になり価値が跳ねた。
   `player.js` の `init(options)` は既に `onClose`/`onPlaying` を受ける構造で `onNavigate`
   追加は自然な拡張。HLS の fail-fast 設定(ザッピング用)は導入済み。
   Media Session のメタデータは現在番組名(`IPTVEpg.nowNext`)とロゴが既に手元にある
2. **テレビ欄の時間窓ナビゲーション**(M・新規)— 現在の窓(今〜+6h)に入るのは
   実データ 33,811 番組のうち **6,667 番組(約 20%)だけ**。残り 25,545 番組が描画可能なのに
   見る手段が無い。`state.timelineStart` が既にパラメータ化されているため、
   ±6h ボタンと「今へ戻る」で書き換えて再描画するだけで基本形が成立する
3. **番組タイトル検索**(S)— 33,811 番組タイトルが既に手元にある。拡張点は
   `applyFilters` のトークン照合 1 箇所のみ(線形照合 8.2ms 実測、150ms デバウンス内)。
   テレビ欄が結果の受け皿になるので「番組から探す → 時間軸で見る」が完結する。
   §2-3 のエンティティ復号を同梱すること
4. **フィルタ状態の URL 共有**(S)— トップ 5 実装で共有したい状態が倍増した
   (地域・テレビ欄ビュー・最近見た順・折り畳みパネルの開閉)。同じ工数で得られる価値が実装前より大きい。
   候補 3 と同時にやると新設の検索状態も最初から共有可能で手戻りが無い
5. **Playability 履歴・前回比レポート**(S)— テスト CI が通り運用系を足す土台が整った。
   EPG ブロックサイト事件(9 サイトが静かに 0 件化し 199ch を浪費)で
   「静かな崩壊」の実害が実証済み。`playability.json` の `counts` を前回と比較して
   ジョブサマリ出力 + 急落で fail。同じパターンを `grab-epg.yml` のサイト別番組数
   (集計・ログ出力は実装済み)に当てれば自動デナイリストへの一歩が実質無料

### 実装時の一般的注意

- どの機能もこのリポジトリの慣習に合わせること: ハーメチックテスト必須(tests/helpers.js の
  ルーティング機構)、EPG 関連は擬似クロック凍結(tests/epg.spec.js 参照)、
  データが無い環境でのグレースフルデグラデーション
- 複数候補が同じ基盤を共有する組み合わせ(州別+エリア表示、
  ザッピング+MediaSession+ショートカット、番組検索+URL 共有)はまとめて実装すると効率が良い
- 時刻・タイムゾーンに関わる実装をしたら、`TZ=Asia/Tokyo npx playwright test` でも
  通ることを確認する(第 3 ラウンドでホスト TZ 依存の flake が実際に出た)

## 4. 次セッションの始め方

1. `git fetch origin epg-data && git checkout FETCH_HEAD -- data/epg` でローカルに番組表データを展開
   (無くてもアプリは動くが EPG UI が出ない。`data/epg/` は gitignore 済みだが
   `git checkout <ref> -- path` は索引に載せてしまうので、コミット前に
   `git restore --staged data/epg` すること)
2. `npm ci && npm test` でハーメチックテスト 104 件が全通過することを確認
3. 実データでの確認をしたければ README の手順で `tests/fixtures/realdata/` を取得
